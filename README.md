# 豆类结构配方放大

服务用于追踪豆类冷冻结构化实验和中试执行差异，使配方、设备与质构结果可以稳定比较。

项目当前提供稳定的基础服务入口，便于本地联调和运维巡检。运行 `python3 service.py --check` 可核对服务配置；执行 `python3 service.py --port 8000` 后访问 `/health` 可确认服务身份。

## 共享产线过敏原换线放行

中试工厂在同一条结构化产线上轮换豌豆、蚕豆和含麸质物料。服务把换线清洁与放行
从纸面清场记录搬到与实际设备段、待放行批次一一对应的领域模型上：

- **换线计划只从真实生产顺序生成**（`POST /lines/{line}/sequence` 登记顺序，
  `POST /lines/{line}/plans:generate` 生成），按产线段登记上一批物料、拆洗步骤、
  清洁验证样本、检测限和下一批标签声明；同一过敏原画像的连续批次共用一个清洁窗口。
- **操作员完成拆洗步骤，实验室签收样本并出具结果**；质量授权人只对覆盖完整且
  检测满足阈值的批次放行（`POST /batches/{id}/release`）。清洁结论、配方版本和
  标签快照在同一事务中生效；放行按批次与幂等键双重去重，服务恢复（`--db` 数据
  文件重开）后重试不会产生第二张放行单。
- **抽样失败**立即隔离同一清洁窗口内尚未出厂的批次；已出厂部分生成可追踪风险
  处置（含通知范围），原检验与放行记录不被改写。确认性复测样本可经
  `POST /plans/{id}/samples` 追加，失败同样触发处置。
- **返工、设备旁路、计划外插单**（`POST /lines/{line}/events`）会重新计算受影响
  范围：过时的计划被取代，已结论窗口范围失效时同样执行隔离与风险处置。
- **同一采样编号的相同重传复用结果；异内容重传立即冻结**样本与所在清洁窗口。
- 隔离批次需质量授权人**例外批准**（`POST /batches/{id}/exceptions`）后方可放行，
  放行单记录例外编号。
- `GET /batches/{id}/trace` 从成品反查换线责任（操作员/实验室/质量授权人）、
  样本证据、例外批准及通知范围。

数据默认持久化到 `changeover.sqlite3`（可用 `--db` 指定，`--db :memory:` 为纯内存）。

## 测试与构建

执行完整测试：

```bash
npm test
```

执行编译检查：

```bash
python3 -m compileall -q .
```

两条命令都可在单个 Linux 应用容器内直接运行，不需要额外服务。
